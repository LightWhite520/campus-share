# Campus Share

OpenWrt / LuCI 校园网共享出口管理插件。管理员动态选择空闲 DHCP 接口，舍友通过邀请链接选择电脑或手机、领取出口并认证。仅在 HTTP 联网检测成功后，出口才加入选定的 mwan3 策略。

**不内置当前路由器的出口名称、MAC、账号或密码。** 接口池、内网接口、mwan3 策略及认证入口均通过配置读取。

## 接入流程

1. 在 OpenWrt 创建 DHCP 出口（物理口、VLAN 或 macvlan 均可），设置独立 MAC / DHCP client ID，加入具有 IPv4 NAT 的出口防火墙区域。
2. 出口保持停用自动启动，且未被现有 mwan3 成员引用。
3. 在“网络 → 校园网共享”选择已有 mwan3 策略，点击“扫描并导入空闲接口”或手动添加出口池；每个槽位使用唯一的 200–239 路由表编号。
4. 保存应用后，管理员生成邀请链接，发给一位舍友。
5. 舍友连接本地 Wi-Fi、关闭移动数据和代理，打开邀请链接，选择电脑（默认）或手机，再领取出口。
6. 插件按所选 MAC 模式配置出口及匹配的 DHCP client ID；将领取设备的 IPv4 流量固定到该出口，获取地址后显示校园网认证按钮。
7. 出口就绪后，舍友在邀请页填写自己的账号密码。插件从该出口获取最新认证参数，使用所选设备类型的 User-Agent 转发登录请求；检查到指定出口返回预期联网检测正文后，将它作为等权成员加入选定策略。
8. 管理员可释放出口。未完成认证的占用默认十分钟自动释放。

同一设备只能领取一个出口。邀请只能由领取它的设备继续使用。随机 MAC 变化时应释放旧出口重新领取。当前版本面向可信宿舍局域网；MAC 绑定不等同于强身份认证。

## 实现边界

- 出口不按物理口名称限制。原有 WAN、LAN2 或其他 DHCP 上联可在管理页选择“转为共享出口”：备份 network/mwan3/campus_share 配置，停用指定接口，移除其在所有 mwan3 策略中的成员关系，再扫描导入分配池。该操作会中断选中线路；之后释放只恢复领取前身份并停用接口，不恢复转换前的主上联用途。内网接口、非 NAT 区接口、已领取接口及与其他启用接口共用设备的接口拒绝转换。普通扫描不会接管现有上联。

- 账号密码只在用户点击登录时临时转发，不写入配置、状态文件、日志或浏览器存储，不自动重试登录。密码在提交完成或失败后从页面清空，curl 通过标准输入接收编码后的认证 URL，凭据不进入进程参数。当前原认证协议和本地接入服务均为 HTTP，适用于可信内网。
- 支持两种出口 MAC 模式，在“共享设置 → 出口 MAC 模式”选择：随机 MAC（默认）为每次领取生成新的本地 MAC；认证客户端 MAC 从内网邻居表读取领取设备的 MAC 并用于出口。两者均设置匹配的 DHCP client ID，释放时恢复原接口设置。
- 模式切换仅影响新领取的出口，已领取的出口需释放并重新领取。旧配置没有 `mac_mode` 时继续使用随机 MAC。
- 邀请页可选择电脑或手机，默认电脑。两种 MAC 模式均按所选类型生成出口主机名：电脑使用 `DESKTOP-` 加 7 位随机大写十六进制字符，手机使用 `Android-` 加 12 位随机小写十六进制字符。
- 若领取浏览器的 User-Agent 识别类型与选择一致，优先读取本地 dnsmasq DHCP 租约，以领取设备的 IP 与 MAC 同时匹配未过期记录，将有效名称用于出口 DHCP。类型不同、未知或名称缺失、过期、不合法时使用上述随机名称。租约名称支持单个 ASCII 主机标签（字母、数字及中间连字符，最多 63 字符）。默认读取 `/tmp/dhcp.leases`，优先使用首个 dnsmasq 配置的 `leasefile`。这是设备上报的 DHCP 名称，无法保证等于系统显示名；桌面模式或修改过的 UA 也可能导致类型识别不准。
- 选择及最终名称在领取时保存，邀请页刷新、重复领取和健康检查不会重新生成或改变。要切换类型需释放并重新领取。
- 邀请页登录适配 `portal.do → PortalJsonAction.do → quickauth.do` 协议：发现入口、读取页面、获取配置和提交认证均使用所选电脑/手机 UA，并绑定已领取出口的 IPv4 地址。认证参数从该出口实时获取，MAC/主机名来自领取状态；不复用分享链接里的设备参数。不会改动浏览器全局 UA。原页面备用入口仍使用真实浏览器 UA；验证码、额外交互或不支持的协议需转到原页面。上游最终设备分类仍需真实账号验证，登录接口成功不等于联网成功。
- 释放时恢复领取前的主机名配置；旧版本已领取记录不修改主机名。名称在新领取时更新，不因设备改名而自动重连；这不是完整设备指纹模拟，也不会清除上游历史记录。
- 客户端模式下，开启随机 MAC 的设备使用当前连接的 MAC；请保持它稳定，变化后释放旧出口再重新领取。同一 MAC 不应同时通过其他连接接入校园上游。
- 已领取设备固定使用自己的出口；其他设备由 mwan3 分流。
- 使用 HTTP 正文验证，不把“能 ping”当作认证成功。
- 认证失效连续三次后移出共享策略，进入重新认证状态。
- 专用路由表包含不可达默认路由，未认证/断链时不会静默借用其他出口。
- 接入设备的 IPv6 转发被阻止，避免绕过 IPv4 出口分配；不管理 IPv6 校园认证。
- 邀请链接含敏感令牌，只在本地分享；网页不加载外部资源。
- flock 序列化领取；不覆盖已启动接口、其他 mwan3 成员或同设备上的现有逻辑接口。
- 逻辑出口数量不等于独立带宽；macvlan 仍共享父物理口和 AP 上联。
- 不保证系统自动弹窗。通过邀请链接接入，路由器已联网时系统通常不会自动弹认证页。
- 私有状态保存在路由器 /etc/campus-share，禁止进入 Git；失败计数存放 /var/run。

## 安装与卸载

依赖：OpenWrt firewall4、mwan3、LuCI、curl、jsonfilter、flock、conntrack；macvlan 另需 kmod。

将项目复制到路由器，执行：

```sh
sh scripts/install.sh
```

安装器备份配置，建立单独的内网 HTTP 接入服务和防火墙例外，不启用任何出口。默认端口 8088，在 /etc/config/campus_share 配置。更改绑定内网/端口后重新运行 /usr/libexec/campus-share-setup。

```sh
sh scripts/uninstall.sh
```

卸载先释放本插件的出口，保留私有状态供检查。Makefile 提供 OpenWrt feeds 构建入口；源码安装是直接验证路径，没有预编译 apk。

## 检查

开发机：

```sh
node tests/frontend-check.mjs
```

OpenWrt：

```sh
sh tests/router-tests.sh
```

路由器测试使用独立 UCI、状态目录和模拟网络命令，覆盖并发领取、占用保护、令牌校验、健康检查、超时释放和跨站拒绝，不启用实际测试出口。真实舍友账号接入仍需实际设备验证。

## 文件

- root/usr/libexec/campus-share：分配、认证检测、路由、mwan3。
- root/usr/libexec/campus-share-portal：认证请求转发、设备 UA、临时会话与出口身份校验。
- root/www-campus-share：自助接入页面及 API。
- htdocs/luci-static/resources/view/campus-share/manage.js：LuCI 管理页。
- root/etc/config/campus_share：通用配置。
- scripts：安装与卸载；tests：隔离测试。
